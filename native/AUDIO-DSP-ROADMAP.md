## Confirmed source path

- Petari `dsptask.cpp` contains the `jdsp` DSP microcode image and starts it through `DspBoot`/`DSPAddPriorTask`.
- A host compile probe of the original `dsptask.cpp` succeeds with the existing Windows compatibility headers and legacy `TRUE`/`FALSE` macros. That original probe object is not integrated; the host link now uses `native/src/dsp_boot_hle.cpp` instead of its Wii MMIO/DSPAddPriorTask path. The host provider validates the ROM upload and startup mails but does not execute the Zelda microcode or schedule later DSP tasks.
- Petari `dspproc.cpp` encodes table setup, frame sync, ARAM address, mixer, and halt commands, then waits for DSP mail/callback completion.
- Petari `JASAudioThread.cpp` starts DMA, boots DSP and waits for DSP-mail callbacks; its callback busy-polls `DSPCheckMailFromDSP` and expects the original JAudio2 protocol.
- Petari `RVL_SDK/dsp/dsp.c` reads and writes Wii DSP MMIO registers directly. Those functions cannot be replaced with a constant mailbox-ready result: command senders would either spin or accept commands without executing them.
- `Native::DspAddressSpace` provides bounded 32-bit DSP-visible addresses for 64-bit host buffers. Host-generated copies of original `JASAiCtrl` and `JASDSPInterface` route DMA frame endpoints and DSP table pointers through a shared registry instead of truncating pointers. The native AI adapter resolves bounded PCM spans from that same registry and feeds them to Windows waveOut; no DSP consumer resolves DSP command/table addresses yet.
- `Native::DspMailbox` provides one-word, full/empty TX/RX mailbox state and a backend interrupt hook. With the ROM HLE not explicitly started, an outgoing word remains pending until a consumer reads it; the transport fabricates no DSP acknowledgement. When started, the SDK mailbox entry points pump only the bounded ROM-upload state machine.
- `DspRomBootHle` models only the ROM upload sequence used by Petari `__DSP_boot_task`: it consumes the ordered A001/C002/A002/B002/D001 mail pairs, validates a bounded mapped image, checks the big-endian HashEctor against `0xD643001F`, then produces the ROM-to-Zelda startup mails. `nativeDspBeginRomTask` starts this over the actual SDK mailbox functions. It does not replace `DspBoot` or acknowledge later Zelda render/audio commands.
- The Petari `jdsp` image is 0x1F00 bytes in guest big-endian word order and hashes with Dolphin's HashEctor to `0xD643001F`. Dolphin's pinned reference maps that exact hash to its Zelda UCode implementation with `NO_ARAM | MAKE_DOLBY_LOUDER | COMBINED_CMD_0D`, explicitly including Super Mario Galaxy. `test-dsp-ucode-hash.ps1` reproduces the byte-order/hash check and verifies the optional pinned-reference match.

## DSP interpreter reference review

An isolated sparse checkout of Dolphin's DSP sources is kept in `../external/dolphin-dsp-reference` at commit `e2ad09306e6d371f7272205bdc363da9fe05fe08`. The checkout includes the DSP core/interpreter and DSPHLE ucode sources for reference; it is not compiled or linked into the port. The upstream repository labels most source GPL-2.0-or-later and notes that file-level licenses vary. Before bundling any source, inspect its SPDX header and settle distribution/license compatibility. Petari itself has a CC0 license, but that alone does not relicense other dependencies or proprietary game data.

The DSP interpreter is not a whole Wii emulator; it would execute the original game's DSP microcode while the PC port continues to use native game code and rendering. The reference is not a drop-in library: its core has Common/Event, analyzer and host-interface dependencies that need an explicit standalone boundary. A specialized native HLE remains an alternative only if it reproduces the actual `jdsp` command and PCM behavior rather than returning fabricated success messages.
