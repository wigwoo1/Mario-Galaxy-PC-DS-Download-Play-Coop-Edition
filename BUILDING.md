# Building diagnostics

Requires Windows x64, PowerShell, Git and Zig matching tools/zig-package.json. The compiler itself is not vendored. The local layout expects tools/zig-x86_64-windows-0.16.0/zig.exe.

From the checkout, the existing setup/probe commands are:

    powershell -ExecutionPolicy Bypass -File publishing/prepare-build.ps1
    powershell -ExecutionPolicy Bypass -File native/build.ps1

The setup helper downloads the official pinned Zig archive and checks its SHA-256, prepares diagnostic support and fetches a pinned Dolphin reference. It has not been tested on a clean computer. native/build.ps1 builds the probe and runs self-tests plus DSP component checks. Other native/test-*.ps1 scripts check narrower components; some need your own game image or generated resources.

## November 4 audio checks

The renderer source and license notices are included under native/third_party/dolphin-zelda; native/generate-zelda-audio-renderer.ps1 checks imported hashes. Preserve those notices and corresponding source for derived builds. The separate DSP-disassembly audit also references local Dolphin SDK/disassembler material outside this publication; its reference setup is not a clean-checkout reproduction claim.

Focused wrappers now include test-jas-channel-lifecycle.ps1, test-jas-stream-lifecycle.ps1, test-jai-stream-manager-lifecycle.ps1 and test-native-dvd-reopen.ps1. The retail tests currently contain the development computer's local WBFS path and need locally supplied game data. Some callback/provider fixtures are generated by prerequisite test wrappers. Published source availability does not prove these commands work unchanged on a new machine.

New focused wrappers include `native/test-audio-dac-dma.ps1`, `native/test-audio-thread-lifecycle.ps1` and `native/test-audio-thread-retail-stream.ps1`. The first checks exact DAC transfer methods with real heaps/native AI; the second executes the complete original thread with a synthetic voice; the third supplies a one-entry sound table pointing to the user's retail stream and executes real audio/DVD workers without playback fences. It still needs the local WBFS path encoded in the wrapper. These checks do not establish clean-checkout reproducibility or full game playback.

Later development verified the queue edit with 32/48 kHz cadence, owned-buffer protection, callback stop/restart and `native/test-native-audio-ai.ps1 -NoDevice`. The retail test now has a 95%–110% timing gate and passed at 26.410 seconds for 26.308 seconds nominal. `native/test-audio-thread-stream-pause.ps1` checks individual/manager pause and paused stop on actual workers. `native/test-audio-pool-destroy.ps1` checks the exact original generic-pool methods and real heaps, including normal destruction and containing-heap reclamation. It requires the allocating heap to remain alive. Larger worker fixtures still retain process-lifetime backing; their success does not prove static shutdown safety. Full system restart, audible game fidelity and clean-checkout reproducibility remain unverified. See docs/verification/2026-11-04-audio-timing-pause-pool.md.
